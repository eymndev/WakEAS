# WakEAS agent notes

- This is one Xcode app target/scheme, `WakEAS`, for iOS and macOS; there is no test target or package manifest. Verify platform-specific edits with `xcodebuild -project WakEAS.xcodeproj -scheme WakEAS -destination 'generic/platform=macOS' build` and `xcodebuild -project WakEAS.xcodeproj -scheme WakEAS -destination 'generic/platform=iOS Simulator' build`.
- `WakEAS/ContentView.swift` contains the `@main` app, UI, and closed-eye/alarm timing; `EyeMonitor.swift` owns camera authorization, capture, and eye readings. iOS devices supporting ARKit face tracking use blend shapes; macOS and other iOS devices use AVFoundation + Vision landmarks. `EASAlarmSound.swift` synthesizes the looping tone; `EASAlarmView.swift` displays the alarm.
- The target sets `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`. Capture/ARKit delegate callbacks are `nonisolated` and send readings to the main actor; preserve this boundary when changing tracking.
- Camera access needs both the generated Info.plist's `INFOPLIST_KEY_NSCameraUsageDescription` in `WakEAS.xcodeproj/project.pbxproj` and, on macOS, `com.apple.security.device.camera` in `WakEAS-macOS.entitlements`. The camera prompt in the project file is currently Turkish even though the in-app UI is English.
- The Xcode project uses a file-system-synchronized `WakEAS/` group: Swift, `AlertNotification.caf`, and `Assets.xcassets` are included automatically. Do not add a Copy Bundle Resources phase for them. `tools/GenerateAssets.swift` is a manual generator, not a build phase; run it with `swift tools/GenerateAssets.swift` from the repo root to redraw the icon and notification tone.
- `EyeMonitor`'s iOS `arView` is `lazy` and must stay `@ObservationIgnored`; `@Observable` macro expansion cannot initialize that stored property.
- `ContentView.tick` ignores readings older than `monitor.lastReadingAt` (0.35 s on iOS, 0.8 s on macOS) so a paused camera cannot keep the closed-eye timer running. `VisionProbe`/`EyeTrack` run with `lenient` thresholds on macOS because Mac eyelid apertures measure smaller; do not unify the two platforms' thresholds.
- Alarm dismissal is manual via the × button. Do not restore eye-open auto-dismiss. On iOS the × is a `.topTrailing` overlay in `EASAlarmView` rather than a header item, because a header row overflowed the narrow screen and pushed the button off-display. On iOS, `AVSpeechSynthesizer.usesApplicationAudioSession = false` so speech ducks a playing MusicKit song instead of stopping it.
- `AlarmSettings.swift` persists sound/theme and per-line TTS text/languages with `@AppStorage`; `MusicAlarmPlayer.swift` resolves selected library songs by MusicKit ID. Apple Music needs `NSAppleMusicUsageDescription` and the MusicKit App Service on the explicit App ID.
- `CompanionLink.swift` pairs a foreground Mac (`NWBrowser`) and iPhone (`NWListener`) over Bonjour `_wakeas-link._tcp`. Do not switch it to MultipeerConnectivity. Keep `NSBonjourServices` as an array in `WakEAS-Info.plist`; a string `INFOPLIST_KEY_NSBonjourServices` does not emit the required array. Local-network usage text belongs in both build configurations, and the macOS sandbox also needs `com.apple.security.network.client` and `.server`. The iPhone alert sound is the bundled `AlertNotification.caf`, not a file written into `Library/Sounds`.
